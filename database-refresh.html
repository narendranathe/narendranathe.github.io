Idempotent database provisioning

I built and deployed an Azure DevOps replacement for a legacy .NET refresh tool, with Contained Always On Availability Group support and idempotent state handling.

My responsibilityDesigned, built & deployed the replacement workflow
UsersTesting & IT
Outcome~1 hour manual effort saved / request · 20+ daily refreshes

Provisioning requirements

The legacy .NET tool did not support Contained Always On Availability Groups. Testing and IT needed refreshed databases with security, the FULL recovery model, CDC and the listener connection ready for use.

I built and deployed the Azure DevOps replacement. I owned the orchestration and state-handling logic, including how a failed attempt could leave the database partly prepared.

Preflight checks and cleanup

I added state inspection and cleanup logic so failed provisioning attempts could be rerun without improvised manual cleanup. This adds orchestration complexity in exchange for a controlled retry path.
