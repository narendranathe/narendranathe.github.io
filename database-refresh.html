Provisioning a usable database.

A deployed Azure DevOps replacement for a legacy .NET tool, built for testing and IT and designed around Contained Always On Availability Groups.

My responsibilityBuilt & deployed the replacement workflow
UsersTesting & IT
Reported outcome~1 hour manual work saved / request · 20+ daily refreshes

A restore was only part of the job

The legacy tool did not support Contained Always On Availability Groups. Testing and IT still needed refreshed databases, with the security, recovery mode, change capture, and connection path ready for their work.

I built and deployed the replacement in Azure DevOps. The scope was the complete preparation workflow, including how to handle a database left halfway through setup when a prior attempt failed.

The important design was the retry

01 / Compatibility

Build for the actual topology.

The replacement supports Contained Always On Availability Groups. I coordinated restore, security setup, full recovery mode, CDC enablement, and listener validation in the team's Azure DevOps environment.

02 / Partial state

Inspect state before changing it.

I made the copy-and-restore workflow rerunnable. That required handling active replication sessions, orphaned CDC cleanup jobs, restore parameters, and stuck restores with pre-flight race checks.

I accepted more state-handling logic up front to make another attempt possible without improvised manual cleanup.

03 / Operational readiness

Finish at the connection path.

A completed restore is not the whole outcome. Listener validation checks the expected connection path after the surrounding setup. Testing and IT use the resulting workflow; people still own exceptions and follow-up.
