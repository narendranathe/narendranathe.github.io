The old tool met a new constraint.

The legacy .NET refresh tool did not support Contained Always On Availability Groups. Testing and IT still needed database copies, leaving people to coordinate restore and setup work.

My replacement runs in Azure DevOps and includes copy and restore, security setup, full recovery-mode configuration, CDC enablement, and listener validation. It works within the team's existing database and delivery environment.

The decisions behind the workflow.

01 / Fit the actual environment

Support Contained AAG.

The availability-group model is the reason for replacing the legacy tool. The setup has to fit that model; these are not containerized databases.

02 / Plan for interruption

Make the next run deliberate.

A failed refresh can leave partial state. I made the copy-and-restore path rerunnable, with state handling and recovery logic rather than assuming every run starts clean.

03 / Keep it operable

Use the delivery platform.

Azure DevOps keeps the orchestration in the environment the team uses for delivery. People still own requests, validation, and exceptions.

What changed for the users?

Testing and IT use the deployed tool. The supported result is approximately one hour less manual work per request across 20+ daily refreshes.

That means less repeated preparation in this workflow. The team owns the surrounding infrastructure; my contribution here is the refresh automation.
