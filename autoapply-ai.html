Why this matters

AutoApply AI is the strongest public proof that I do more than build isolated AI features. It is a workflow platform with real state, real orchestration, multiple surfaces, and clear product boundaries.

  • The extension is where the user acts.
  • The backend is where the workflow state, retrieval, and provider routing live.
  • The dashboard is where the system becomes inspectable and manageable over time.

Core product loop

  1. Discover roles and surface fit signals.
  2. Tailor resumes and answer generation against the live job context.
  3. Apply through ATS-specific adapters and content scripts.
  4. Track applications, answers, and resumes as reusable system memory.

Workflow architecture

Discover

Job boards and ATS pages

Job context and page structure are detected directly from the user's browsing flow.

Tailor

Resume and answer engines

Retrieval-backed answers and tailoring logic route into the right part of the workflow.

Apply

Chrome MV3 execution layer

Detected fields, questions, and ATS-specific adapters bridge AI output into real application pages.

Track

FastAPI + data layer

Applications, answers, resumes, provider configs, and vault history stay coherent over time.

System boundaries

  • Chrome MV3 handles in-page execution and user context.
  • FastAPI owns workflow orchestration, persistence, and generation endpoints.
  • PostgreSQL and Redis carry application memory, scoring, and stateful behavior.
  • Provider routing keeps quality and latency decisions explicit instead of hidden in one monolithic model call.

Proof points

  • 40+ backend endpoints across the application lifecycle.
  • 9-page dashboard for applications, resumes, vaults, and user configuration.
  • 11 ATS adapters and 6 LLM providers inside one coherent product story.
  • Live deployment and a system that reads as product engineering plus AI infrastructure, not just an experiment.
