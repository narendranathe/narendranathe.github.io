Portfolio risk analytics: integration in progress

An independent Kafka, Spark, Delta Lake, FastAPI, and Streamlit experiment. The streaming-to-API handoff remains incomplete.

Repository Delta writer Current API

What the code currently establishes

A Spark writer consumes Kafka and writes a checkpointed Delta bronze layer. A separate FastAPI service reads CSV files under data/processed; if those files are absent it generates sample data.

The integration gap

The reviewed writer does not supply the CSV path that the API reads. An updating dashboard can therefore be displaying generated samples rather than the streamed market data. It is not evidence of a completed end-to-end pipeline.

Claims I am holding out

I do not use the older throughput, sub-five-second latency, live portfolio-manager usage, production-ready, or cloud-scale claims from earlier project descriptions. Hard-coded local Windows paths also need configuration before the streaming writer is portable.

The next proof

Connect a defined persisted stream output to the API, expose its source and freshness, then test the complete path using known input records. Measure end-to-end latency only after that handoff is working.
