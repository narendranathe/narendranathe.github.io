Structure is not the whole meaning.

I built a Claude Code CLI context harness used by my team. It combines schema-derived relationships and table grain with business meaning that I annotate by hand.

My responsibilityDesigned, built & internally deployed the harness
UsersMy engineering team
PurposeContext for joins, defect diagnosis & code changes

Why schema alone was not enough

Knowing which keys connect two tables does not explain what one row represents or which business interpretation belongs in a calculation. An assistant can produce plausible SQL and still misunderstand the grain.

I built a context model for Claude Code CLI that brings those two kinds of information together: schema-derived key relationships and table grain, followed by manually authored business annotations. My team uses it for defect investigation and writing or fixing code.

The boundary I chose

01 / Generate structure

Start with the schema.

Generate relationship and grain context from schema metadata. This supplies the structural map the assistant needs when reasoning across tables.

02 / Author meaning

Keep domain judgment explicit.

I add business annotations by hand. A key relationship cannot tell the assistant what the team means by a measure or which business assumptions matter for a defect.

03 / Review the result

Context is not enforcement.

The harness informs the assistant. It does not validate every proposed SQL statement or guarantee the right answer. AI-assisted changes still need engineering review and tests.

THE QUESTIONWhat does a sum mean?

Join first, then sum the order total: $84. The original order is $42.

A relationship tells us how to join. Grain and business meaning tell us whether that join supports the calculation we intend.

What changed for the team

The team has a shared context harness for AI-assisted engineering, with both structural information and explicit business annotations. The contribution is a reusable tool and context model that colleagues use in their workflow.

The tradeoff is maintenance: human-authored meaning needs attention as the system changes. I keep that responsibility visible rather than treating metadata generation as a substitute for domain knowledge.

Internal code, schema, and business annotations remain private. The figures use generic concepts and fictional records.

How this connects to my independent work

The employer harness helps a team supply domain context to an assistant. My independent repo-context-hooks project addresses a different boundary: preserving intent, decisions, and next steps between coding-agent sessions. Both make context inspectable, while keeping the responsibility for meaning with the engineer.
