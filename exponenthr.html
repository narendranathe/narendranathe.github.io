The problem

ExponentHR needed an analytics experience that could replace fragile Power BI and DAX workflows with a system that could answer real cross-domain questions without giving up governance or trust.

  • Enterprise clients needed faster answers across payroll, expenses, benefits, and PTO.
  • Cross-domain joins were hard to maintain manually and easy to break.
  • Security could not be bolted on later; row-level and column-level rules had to be part of query execution.

What I owned

The value of the project was not just model selection. It was system design: retrieval, planning, governance, secure execution, and making new domains onboard without fresh engineering effort each time.

  • Catalog-driven retrieval and semantic classification.
  • Join resolution through a semantic graph.
  • Governed SQL generation and validation before execution.
  • Hot-reload admin patterns that reduced onboarding friction.

Sanitized architecture

Input

Natural-language query

User intent arrives as a business question, not a BI-specific artifact.

Retrieval

FAISS domain lookup

Concept and domain indexes narrow the search space across thousands of HR columns.

Planning

Semantic join resolution

Graph-based relationships determine the safest valid path between domains.

Execution

Governed SQL runtime

Generated T-SQL is validated, security checked, then executed within platform constraints.

Why this reads as platform work

  • Retrieval, planning, execution, and governance are intentionally separated.
  • Security is part of the runtime path, not just documentation or UI policy.
  • Hot-reload onboarding moves the platform toward reusable infrastructure instead of one-off project support.

Measured outcomes

  • 400 enterprise clients supported.
  • 6K+ catalog columns across multiple HR domains.
  • About 2 days to onboard new domains without code changes.
  • A public story that demonstrates enterprise AI ownership without exposing sensitive internals.
