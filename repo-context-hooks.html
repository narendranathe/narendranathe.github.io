Independent project · Open source · Package release

A checked-in handoff for coding-agent work

An independent Python tool that keeps project context and decisions in repository files, with Claude lifecycle hooks and explicitly partial integrations for other agents.

Source at reviewed commit CI evidence Package

Why I built it

When a coding session loses context, re-explaining the same constraints and failed attempts becomes part of the work. I wanted a handoff I could inspect in Git, with decisions and next steps that survive a session boundary.

Who it serves and what I built

The tool is for developers using coding agents. It combines checked-in workspace documents, lifecycle scripts, a CLI for initialization and checks, and local operational telemetry. Semantic decisions must be written by the developer or agent; the tool does not infer them from a complete conversation.

The design boundary

Repository files keep the handoff reviewable alongside code. Claude has lifecycle integration; the other documented platforms use partial instruction or export paths, not equivalent automatic hooks. A repository needs its workspace contract before the global scripts do useful work.

Python 3.9 or newer is required. The package declares no third-party runtime dependencies; the installed scripts also need working Python and Git commands in the hook environment.

Try the documented path

python -m pip install repo-context-hooks
repo-context-hooks install --platform claude
cd /path/to/your/repository
repo-context-hooks init
repo-context-hooks verify --platform claude
repo-context-hooks measure --repo-root .

The install command changes the selected agent's local configuration. Run it only in an environment you choose to configure. The verification receipt checks synthetic plumbing; it does not prove every host lifecycle event fired.

What the available evidence shows

The CI log for the reviewed main commit records 632 passing tests and 88.20% coverage on one Ubuntu/Python 3.12 job. That was a successful August 14, 2026 run, not a new test run for this page. The release workflow configures OIDC publishing and provenance attestations; a tagged publish run completed successfully.

These are software-delivery observations, not proof of external adoption, model-quality improvement, or verified signatures on a downloaded wheel.

Measurement and privacy limits

Time, token, and cost savings in the dashboard are estimates based on fixed assumptions. They are not timed before/after measurements or actual bill reductions.

Telemetry is stored in local JSONL files and the reviewed version has no remote collector upload implementation. Hooks intentionally supply selected context to the coding agent and may read GitHub issue metadata through GitHub CLI. Agent and provider settings govern that context.
